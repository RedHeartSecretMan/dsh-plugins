# Changelog

## 0.2.1 — 2026-11-27

- Add a four-tab **Naming settings** modal under the `Session title ›` submenu (available on both cold and live sessions):
  - **Format** tab with a live title preview, `template`, `language`, `topicMinChars`–`topicMaxChars`, `cjkSpacing`, `dateFormat`, `timezone`, and `fallbackTruncation`.
  - **Types** tab with an inline `types` vocabulary editor (add/remove/rename, hints, `provisional` flags with a per-type `maxRefinements`, automatic `fallbackType` sync, restore-defaults). The vocabulary's shared refinement count is what the form writes; `maxProvisionalRefinements` itself stays a raw-config key so the per-type values keep their meaning.
  - **Models** tab with `ctx.llm`-discovered provider/model dropdowns plus manual entry for all three routes: primary (`provider`/`model`), subagent (`subagentRoute`), and fallback (`fallbackRoute`).
  - **Behavior** tab with `uiLanguage`, `subagentDelegationLabel`, AGENTS.md supplements (`enabled` + `maxBytes`), role probe, backfill toggle, and a collapsible advanced request-tuning section (`maxInputBytes`, `maxOutputTokens`, `timeoutMs`, `retryAttempts`, `retryDelayMs`).
  - Compact dirty-only inline reload notice in the modal footer.
- Unify every modal control width into four tiers — `240` (wide), `120` (numeric/short), `48` (compact counters), `28` (icon buttons) — plus a `68` minimum for footer buttons and one `44` switch column, so the vocabulary table, the form rows, and the footer share one right edge. Form controls and row actions are `28` high; the collapsible disclosure bar (`40`), the in-header restore action (`22`), and the YAML toolbar (`26`) keep their own heights because they are not field rows. The 620px frame carries a `scrollbar-gutter: stable` on its tabs, body, and footer so they never shift against each other.
- Give the `/title` command its own transcript row through `conversation.chat.commandview`: a verb chip (`status` / `refresh` / `pin`) distinguishes the operations, a check, warning, or dot carries the outcome, every settled row expands to the command's own output in a host-styled block, and a copy action puts that output on the clipboard. The collapsed line is a one-line summary — the current title for `status`, the pinned or regenerated title without the lead-in for the others. The Host's generic card printed the entire multi-line report in its collapsed row and labelled all four operations alike.
- Tell the settings form when the running Host half is older than the files on disk. The Client half reloads on every edit while the Host half loads once at activation, so a Host-only change silently "did nothing"; the dialog now names the newer module and asks for a DSH restart. Detection compares this module’s own mtimes with the process start time, never blocks saving, and treats an unreadable module as current.
- Tighten `/title` wording and reject bad arguments. `refresh` reads `新标题：…` and adds `已解除固定，自动命名恢复。` when it released a pin; pin reads `已固定：…` plus one line on how to regenerate. An unknown verb or a stray argument answers with a `请用 /title …` hint instead of silently ignoring the input.
- **Breaking for the command line only:** `/title auto` is gone. It did exactly what `/title refresh` does — the Host treats an explicit refresh as a pin release — so the two verbs never differed except in wording. `pin` also no longer requires a title: bare `pin` pins the current title (the menu's 固定当前) and `pin <title>` renames and pins (重命名 + 固定), matching the sidebar menu. The verbs and the menu now name the same three operations.
- Retitle the status dialog to **查看状态 / View status** and give it the same rhythm as the naming-rules card: the current title becomes a section header above its card, and every rule value (template, date source, topic width) renders as the same chip instead of prose beside code.
- Add a developer **YAML configuration** editor on the plugin's detail page via `plugins.bundle.config` (`key: '@redheartsecretman/session-title-template'`), backed by a zero-dependency YAML 1.2 subset parser/serializer (`lib/yaml.js`), supporting full `config` edits (including `backfill.retitle`), expanding full defaults, line-numbered syntax validation, schema validation, and inline-confirmed reset to bundle defaults.
- Persist both settings surfaces through the Harness config editor (`ctx.get('configEditor').edit(ctx.fiber.entry, …)`) behind an owner-only `GET`/`POST /session-title-template/settings` route (`form`, `yaml`, and `reset` modes) instead of rewriting `cordis.patch.yml`. Comments, other plugins' rows, and `!!js` expressions survive; a row a higher patch layer overrides reports `config-overridden` instead of a generic failure; an unavailable editor reports `editor-unavailable`; unchanged writes are skipped; and restart-dropped replies are verified by deep-equal read-back.
- Share the modal focus trap, Escape handling, and frame between the status and settings dialogs (`useModalBehavior`, `ModalFrame`).
- Accept an owner request that arrives without a Peer argument by falling back to the loopback trust test (`lib/owner-gate.js`). Harness 0.2.2 calls a route handler as `handler(req, res)`, so the previous `peer.principal.kind === 'owner'` check answered 403 for every request from the local machine — the settings dialog and the status route were unusable there. A supplied Peer still decides alone; the fallback only runs when it is absent.
- Skip an unreadable `AGENTS.md` candidate instead of aborting discovery. One broken symlink, permission denial, or path the platform refuses to stat used to disable every readable naming excerpt; the candidate now reports a diagnostic and discovery continues.
- **Breaking:** the backup title route moved from `backfill.fallbackRoute` to the top-level `fallbackRoute`. The old key is refused with a migration message instead of being ignored, because the route serves every title request (fallback resolution, retry backup, targeted-retitle preference) and only one of its four uses belongs to the backfill pass — nesting it under `backfill` made `backfill.enabled: false` look like it disabled the route too. Move the same `{ provider, model }` object up one level.
- The History toggle now says it keeps "manually renamed or pinned" titles, matching what the maintenance pass actually skips (`source.kind === 'user'`).
- Rebalance the model-free fallback title. It now derives the topic from the first substantive line instead of the raw first line, so a greeting or a filename listing no longer becomes the title, and the natural truncation prefers a completed sentence before falling back to a clause boundary. `hard` truncation keeps its documented behaviour: it never splits a token, so it can stop short of the width limit.
- Resolve a cold session's title route through the same precedence as a live one (`resolveColdRoute` delegating to `resolveRoute`), so the status snapshot can no longer disagree with naming about which model would be used.
- Merge each provider/model pair through one helper on both sides (`applyRoutePair` in `lib/settings.js`, one loop in `client.js`), so the subagent and fallback routes cannot drift apart from the primary route.
- Collapse the three identical save-failure responses in `lib/settings-route.js` into one helper, move the JSON envelope and bounded body reader into `lib/http.js` so both routes share one response shape, share the unit-walking loop of both truncation modes in `lib/title/text.js`, and let the Host's naming presets carry their template so the Client no longer keeps a second copy of it.


## 0.2.0 — 2026-11-24

- Retry failed title calls instead of giving up after one attempt. One round now walks every configured route (so a healthy `backfill.fallbackRoute` still wins immediately), and later rounds re-walk the set with exponential backoff; `retryAttempts` (default `3`) and `retryDelayMs` (default `500`) bound it. Input-budget failures stay single-shot because they repeat deterministically.
- Record why a title call failed without persisting provider text: the diagnostic log now keeps `route=<provider>/<model> attempt=<n>/<total> <code>: <category>` instead of the bare `title-call-failed` label, so route, timeout, budget, stream and format failures can be distinguished without logging prompt, response or raw error text.
- `describeTitleFailure` / `isRetryableTitleFailure` are exported from `lib/run.js` and covered by `test/retry.test.js`.
- Stop losing AGENTS.md naming guidance. The plugin declared `@deepseek-ai/dsh-agent-instructions` as an optional peer, but the Harness bundles that package inside its application archive: a linked or profile-installed plugin carries no `node_modules`, so the lazy import failed on every prompt and the log filled with `agents-instructions-sdk-import-failed`. The dependency and the runtime import are gone; `discoverInstructionFilesLocally` now covers the documented scope itself — harness home, shared agents home, then repository root through the working directory — deduplicated by realpath and cancelled with the reader.
- Read only `AGENTS.md`. `AGENTS.local.md` personal overlays are no longer requested, so guidance comes from one committed file per scope and a stray local file cannot change titles.
- Observe whether a title instruction actually reaches the model. `roleProbe` sends one tiny request per route that demands an exact token: a model that cannot read the instruction answers something unrelated, which is how an endpoint that silently drops the instruction block is detected. Verdicts are cached per provider/model, logged as `role-probe ... result=supported|unsupported`, and transport failures stay undecided instead of marking the route unsupported. The probe runs detached: it never delays or fails title generation, and it never rewrites the profile.
- Name a subagent from its delegation label. A subagent's first message is a task brief, so deriving a title from messages reads like the brief and costs a model call. `readDelegationLabel` takes the subagent's own `subagent/descriptor` label, and `planTitle` renders it through the configured template, so a delegated session gets a readable title with zero model calls; a later refinement can still supply the precise type. Root sessions never use that source.
- Separate planning from execution. `planTitle` answers whether a session needs a new title, why, and what the fallback and canonical state are, from a plain snapshot object. The provider now only wires stages together, so refresh rules, fallback construction and recovery detection are testable without a session, a route or the filesystem.
- Report title state as one snapshot. `describeTitleState` separates the built-in rules (template, date format, vocabulary, length, spacing) from optional `AGENTS.md` supplements, so a supplement is never mistaken for the whole rule set: the summary reads `内置规则 + N 个补充来源`, and only sources that contributed a naming excerpt are counted. The snapshot also reports title source and pin state, the newest failure category, and the role-probe verdict, without provider text.
- Record diagnostics as structured data. `state.record` appends bounded JSON lines beside the human log, so the status view reads fields instead of parsing log strings. Records are truncated per field, trimmed to a bounded file, and a corrupt line is skipped rather than failing the read.
- Expose the snapshot through `describe_current_session_title`, a read-only tool that answers the whole status question for the calling session, so the snapshot has a production consumer instead of test-only reachability.
- Share streamed-output reading between the title call and the role probe, so a provider quirk fixed in one path also protects the other.
- Scope failure details to the session that produced them. Records carry a `sessionId`, and the status snapshot only reports a failure belonging to the queried session, so one session's timeout no longer explains another's title.
- Name subagents only from their own descriptor. A fork replays its ancestor's events as seed, so an inherited `subagent/descriptor` describes the ancestor; the label reader now requires the session's own origin to be a subagent, and planning takes that flag instead of inferring it from a label being present.
- Normalize a delegation label with the same rules as model output, so a label ending in punctuation still yields a canonical title instead of one the parser would reject.
- Probe every candidate route, not only the primary: a fallback endpoint can drop the instruction block just as the primary can.
- Write structured records under the same cross-process lock as the human log.

### Added in 0.2.0

- **A sidebar UI half, delivered in the same package.** `client.js` adds a native `会话标题 ›` submenu (three operations, host icon column, disabled rows explained, reactive `observe()` updates), a title-status icon at the end of each row, a hovercard-themed status section in the row's hover card, and a `shell.overlay` modal dialog for viewing full naming status. No new Remote method was needed: the Client reaches the Host through owner-only `webServer` routes (`GET /session-title-template/status` for live and cold sessions, `POST /session-title-template/refresh` for silent live regeneration), falls back to `ctx.remote.commands.execute` before a Host reload, and pins through `ctx.sessions.using(..., ref => ref.binding.session.rename(...))`, so a profile-installed plugin still resolves no package from the Harness archive.
- **Title status reaches the Client as a projection.** `lib/projection.js` registers a `sessionTitleState` wire unit on `ctx.sessionProjections` with `summary: true` (awaited directly in `apply()`), so every Session list row carries the title, its source and its pin state. The Client reads it from `sessions.list` and never polls. The schemas are structural — the registry only calls `.parse()` — which avoids a `zod` dependency a profile-installed plugin cannot resolve.
- **`/title` command** with `status`, `refresh` and `pin [title]` as the in-session entry point and fallback command path. In the sidebar menu, `查看状态` works for both live and persisted cold sessions via the read-only HTTP route, `自动生成` stays disabled with an explanation on cold sessions, and `固定当前` resumes a cold session via `SessionFace.rename` (and disables when already pinned or untitled).
- **`backfill_session_titles` tool**, opt-in with `backfill.enabled`. It previews by default (`dryRun` true) and refuses to write without the exact ids a person approved, so historical repair cannot be an implicit bulk rewrite.
- **Six named generation stages** in `lib/title-runtime.js` replace the previous single closure: resolve context, decide plan, select input, resolve targets, compose prompt, call with retry. Each takes and returns plain objects, so a policy rule is tested by calling one stage instead of building a whole plugin context.
- **`lib/title.js` split** into `title/text.js` (cleaning, CJK spacing, width, truncation), `title/format.js` (template, rendering, parsing) and `title/prompt.js` (instructions, framing, budget). The old module remains as a re-export shim for one release.
- Native menu rendering and UI polish: the overlapping Regenerate and Resume automatic actions are merged into one `自动生成` entry using the sparkle icon, leaving three concise actions (`自动生成` / `固定当前` / `查看状态`) under the native `会话标题 ›` submenu. The parent row uses a text-lines glyph instead of Rename's pencil, and the three title states share one star-based visual family across the menu, row indicator, hover card and status dialog — free sparkle for automatic, corner-framed star for pinned (distinct from Pin Session's pushpin), and dashed-ring star for temporary fallback. `查看状态` consumes the Host route's structured `snapshot` directly for fully localized zh/en dialog rendering (with focus trapping, focus restoration, and request cancellation on close), and `自动生成` uses `POST /session-title-template/refresh` with in-flight feedback and concurrency deduplication so neither action appends `/title` command blocks into the active conversation. The sidebar hover card section uses the host's hovercard label tokens and aligned two-line icon-row layout across all three title states.
- `scripts/verify-client.mjs` loads `client.js` the way the Web carrier does and checks the plugin shape, slot and menu contributions (`observe` included), dictionary parity, submenu structure, pin path and guards, cold-session behavior, hovercard styling, bilingual snapshot modal rendering, abort behavior, structured HTTP error handling, and the silent refresh route. `npm test` runs it, so a broken Client half fails before packaging.
- 336 tests and 20 Client checks.

### Fixed in 0.2.0

- `role-probe` diagnostic records now carry the `sessionId` that was being named, so one session's verdict cannot explain another's status.
- A reply the parser rejects, or one truncated by `maxOutputTokens`, is no longer re-requested from the same model in the same round; the next configured route takes over instead, so one malformed answer no longer costs three identical calls.
- Harness failure codes (`SESSION_TITLE_TIMEOUT`, `TITLE_TOOL_OUTPUT`) are now classified by code rather than by provider message text, and a truncated reply is reported as its own `output-truncated` category with dedicated advice.
- Route resolution reads the `modelSelection` projection through the supported `snapshot()` face (falling back to the deprecated `stateOf()` only on older Harness) and honours a pending model switch, so a title follows the model the user just chose instead of the previous one.
- `FAILURE_ADVICE` in `lib/title-command.js` now covers `timeout` and `output-truncated` (all 7 categories from `describeTitleFailure`), `renderTitleStatus` displays failure timestamps, and `describeTitleState` suppresses stale failures once a newer provider title or model evaluation succeeds.
- Provisional titles (`探索`) that pass `maxProvisionalRefinements` now hand over to `low-overlap` and `periodic-audit` instead of being frozen more strictly than settled titles, and count eligible messages rather than an in-memory counter that resets on restart.
- Removed the unused `formatDate` call from `describeSession` in `index.js` (which could fail read-only status inspection when `createdAt` was missing), bounded per-session bookkeeping maps, and bounded `roleProbe.drained()` during unload so a hanging endpoint cannot stall disposal for 15 s.
- `applyBackfill` reuses the session snapshot already read during eligibility inspection and reports missing requested ids as `not-found` instead of silently dropping them.
- `MAX_UNKNOWN_ATTEMPTS`, `SUBSTANTIVE_MIN_CHARS`, `LOW_OVERLAP_RATIO`, `STATE_DIR_NAME`, `canonicalType` and `titleAnchor` are no longer exported: nothing outside their module consumed them.
- Role-probe interface narrowed from `{ probe, status, detail, idle }` to `{ ensure, verdictOf, drained }`: `status` had no production consumer, and the two readers had drifted.

## 0.1.3 — 2026-11-16

- Stop cutting titles mid-word: `topicMaxChars` now measures CJK-equivalent width (Han 1, ASCII 0.5, CJK spacing 0) and truncates on whole tokens, so mixed CJK/English topics such as `open-code-review 支持 Bitbucket CI` survive intact. Default moves from `18` to `20`.
- Truncation keeps a complete clause: when a parallel clause would lose its object, the title falls back to the completed first clause instead of ending on `与修复`, and a leftover connector such as a trailing `与` or `-` is removed. Conjunction detection compares whole segmented tokens, so `合并`, `涉及`, `并发`, `校验和`, and `重定向` are never mistaken for separators.
- An atomic token (scoped package name or ASCII identifier) is split only when that single token exceeds the whole budget.
- Both prompt languages now state the width unit and forbid cutting a word short or stitching unrelated tasks together.
- Register the rename and refresh tools with plain JSON Schema instead of importing `@deepseek-ai/dsh-tools` at runtime. This fixes linked/profile installs where the plugin directory cannot resolve the Harness SDK and the whole plugin fiber fails with `Cannot find package '@deepseek-ai/dsh-tools'`.
- 191 tests.

## 0.1.0 — 2026-11-04

- Template-shaped session titles: configurable `[date][type] topic` template, date from the session creation time, controlled type vocabulary, CJK spacing and Unicode-aware topic limits.
- Stability policy: canonical titles are retained; provisional titles refine within a bounded message window; deterministic fallbacks remain recoverable.
- Model calls use the current session route with an explicit backup route, the lowest reasoning effort, bounded input/output budgets, timeouts, cancellation and a `session/title-llm-request` record.
- Optional AGENTS naming guidance from applicable `AGENTS.md` / `AGENTS.local.md` files, with byte budgets, scope ordering and fail-soft diagnostics.
- Current-session tools `rename_current_session` and `refresh_current_session_title`, with official title APIs, flush and read-back.
- Optional historical backfill with read-only eligibility checks, pinned-title protection, resumable state and durable completion markers.
- 158 tests and an installed-Harness contract check.
